# Google Play — Data safety form

The answers, written out so submitting the form is transcription rather than
authorship. Every one of them is a statement about the code and can be checked
against it; the paths are given.

## Does your app collect or share any of the required user data types?

**No.**

The app has no account, no sign-in, no analytics SDK, no crash reporter and no
advertising identifier. It makes no network request at runtime at all: every
asset is packaged and served from the app bundle over the local `https://localhost`
scheme, and `scripts/qa-native-android.mjs` asserts that on a running device.

| Question | Answer | Where to check |
| --- | --- | --- |
| Personal info | Not collected | no field asks for a name, email or age |
| Financial info | Not collected | purchase is handled by the store, not the app |
| Health and fitness | Not collected | — |
| Messages, photos, contacts, calendar | Not collected | the app requests no such permission |
| Location | Not collected | no location permission is declared |
| Files and docs | Not collected | the app reads and writes no file outside its own container |
| App activity | Not collected | practice history is written to the device's own database and never leaves it |
| App info and performance | Not collected | no crash or diagnostics reporting is integrated |
| Device or other identifiers | Not collected | no advertising id, no `ANDROID_ID` read |

## Is all user data encrypted in transit?

Not applicable — no user data is transmitted. The app performs no network I/O.

## Do you provide a way for users to request that their data be deleted?

Yes, and it does not require asking anyone: **My Learning → Reset → Reset
learning progress** clears everything the app has stored on the device. There is
no server copy to request the deletion of.

## Permissions declared

| Permission | Why |
| --- | --- |
| `INTERNET` | required by the Android WebView to load the app's own bundle over the local `https://localhost` scheme. No remote host is contacted; the release security audit scans the packaged bundle for development or remote origins and finds none. |
| `POST_NOTIFICATIONS` | the optional daily study reminder. Off by default; the system prompt appears only when the learner switches it on and picks a time. Nothing is scheduled anywhere but on the device, and no notification carries learner data. |
| `VIBRATE` | the short haptic tick when a stroke is accepted. `@capacitor/haptics`, used only there. |
| `RECEIVE_BOOT_COMPLETED` | re-registers the daily reminder after a restart, because Android drops pending alarms on reboot. Not prompted for. |
| `WAKE_LOCK` | delivers the reminder on a sleeping device. Not prompted for. |
| `com.talkhangyul.ganada.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | generated by AndroidX for its own internal broadcast receivers; it grants nothing to the app and is not user-visible. |

`POST_NOTIFICATIONS` is the only permission in Play's *dangerous* group, it is
the only one the learner is ever prompted for, and the prompt is shown at the
moment they ask for the feature rather than at launch. The full audit, read out
of the built APK rather than out of the source manifest, is in
`permissions-audit.md`. `node scripts/audit-release-security.mjs <apk>` reads the
built package and fails if any other dangerous permission appears.

### The reminder does not change any answer above

A local notification is scheduled by the app, on the device, for the device. No
data is collected to schedule it, none is transmitted, and the notification text
is a fixed string from the translation bundles — it does not name a word, a
streak, or anything else about the learner.

## Target audience and content

The app teaches an alphabet and beginner vocabulary. It contains no user-generated
content, no social features, no messaging, no external links out of the app other
than the licence links on the Content sources screen, and no advertising. See
`ads-declaration.md` and `target-audience.md` for the corresponding forms.

## Families policy

The app is suitable for all ages and does not target children specifically. It
collects nothing, so the Play Families requirements on data collection do not
apply. If the listing opts into a Families category, the answers above are
unchanged.
